# ToxicHR — Burndown

> Боевой UI v1 собран, движок V3 работает вживую с OpenAI. Полный поток
> протестирован на живом сервере: резюме → разбор → шаринг → кабинет.

---

## Новая главная с ведущим HR — 26 августа 2026

- Первый экран перестроен вокруг одного активного HR: крупный портрет, характерная реплика и понятная специализация вместо четырёх конкурирующих карточек.
- Вадик выбран сразу, поэтому основной CTA доступен без лишнего шага; остальных HR можно переключать компактной лентой.
- Главный сценарий честно называет загружаемый документ резюме, а разбор вакансии вынесен в отдельный вторичный маршрут.
- Реплики направлены только на резюме и формулировки, а не на человека.
- Мобильная композиция получила собственный порядок блоков и закреплённый CTA для большого пальца.
- После визуальной проверки из hero убраны декоративный бейдж, схема этапов, сервисное уведомление, пунктирная зона загрузки и повторяющаяся фотогалерея.
- Файл и вставка текста стали двумя равноправными способами начать, а портрет показывает пример конкретного замечания вместо одной презентации персонажа.
- По итогам второй визуальной проверки карточки HR возвращены под основной портрет, CTA получил характерный текст «Кидай резюме», а все мелкие подписи и ранняя ссылка на вакансию удалены.

## Надёжность живого разбора — 26 августа 2026

- Исправлено вечное ожидание результата в локальном режиме React: повторный диагностический запуск больше не гасит рабочую загрузку отчёта.
- Клиент дочитывает последнее SSE-событие даже без завершающего разделителя и один раз безопасно восстанавливает оборванное соединение.
- Повторное открытие того же резюме с тем же HR в течение 15 минут возвращает уже готовый или выполняющийся разбор без нового платного запроса к AI.
- Реальный зависший разбор восстановлен из базы и проверен через исходный пользовательский URL; заключение появляется за несколько секунд.
- Добавлен регрессионный тест, который требует одинаковый `analysisId` от двух последовательных потоков.
- Локальная главная снова получает CSS и JavaScript при открытии через `127.0.0.1:3100`: адрес явно разрешён в настройке Next.js для dev-режима.

## Релизный UX-аудит — 24 августа 2026

- На главной скрытые до выбора HR элементы больше не остаются доступными для клавиатуры и автоматических средств чтения.
- До выбора персонажа интерфейс прямо объясняет следующий шаг; после выбора открывается только рабочая зона выбранного HR.
- При вставке слишком короткого резюме сервис показывает, сколько текста ещё нужно, вместо молча недоступной кнопки.
- Мобильная регрессия закрепляет первый экран, отсутствие горизонтального переполнения и понятное состояние короткого текста.
- Вакансия на телефоне стала короче до основного действия: поле не выталкивает кнопку далеко за первый экран.
- Поле вакансии объясняет минимальный объём, показывает сохранение/возврат локального черновика и предупреждает, если показанный результат устарел после правки текста.
- Пустые категории сопоставления теперь объясняют смысл отсутствия результатов вместо ощущения незавершённого отчёта.
- Возврат в улучшение резюме поднимает пользователя к первому незаполненному вопросу и явно сообщает, сколько ответов восстановлено из черновика.
- Пустой кабинет больше не ведёт только в один сценарий: новый пользователь может начать с резюме или с вакансии, а сохранённые вакансии не теряются из маршрута.
- После релизного UX-аудита все три продуктовых коммита прошли GitHub CI: ESLint, TypeScript, production build и полный Playwright-набор.
- Локальная инструкция приведена к реальному порту 3100 и дополнена безопасным mock-режимом и восстановлением нативного SQLite-модуля на Windows.

## Защита живого AI — 24 августа 2026

- AI-редактура больше не может добавлять в резюме новые содержательные слова,
  технологии, действия или числа: при любой неподтверждённой детали используется
  исходный ответ кандидата.
- Ответ разбора вакансии проходит полную runtime-проверку структуры до попадания
  в интерфейс; сломанный или неполный JSON переводит запрос на безопасный
  эвристический результат.
- Категории «доказано» и «спрятано» сохраняются только вместе с дословной цитатой
  из резюме. Без неё требование автоматически переводится в «нужно уточнить».
- Добавлены регрессионные проверки: выдуманный факт без цифр,
  неподтверждённое число, детерминированное объединение исходной строки с новым
  масштабом, сохранение локальной связи чисел и фактов между ответами и внутри
  одного ответа, различение похожих
  русских слов, короткий фактический ответ, любые неопределённые вступления и
  их распространённые русские синонимы и обещанные продолжения после «но»,
  бессодержательный ответ, неправильная структура AI-ответа и
  ложная положительная категория.

## Спринт восстановления — 13 августа 2026

- Восстановлен рабочий контекст ветки `codex/career-loop-recovery-v2` и PR #1.
- Сквозной путь проверен на чистой SQLite-базе: вставка резюме → первый HR →
  второе мнение другого HR → публичная ссылка → фактическое улучшение →
  сопоставление с вакансией.
- Главная усилена как продуктовый маршрут: drag-and-drop, вставка текста,
  понятные три шага, мобильная лента HR и возврат к сохранённой вакансии.
- Главная retention-фишка выведена в результат: после первого разбора можно
  сразу получить второй взгляд на то же резюме без повторной загрузки.
- Вакансия теперь сохраняется до загрузки резюме, восстанавливается после
  разбора и ведёт к сопоставлению. Результаты можно копировать одним нажатием.
- «Реванш» превращён в пошаговый сценарий с прогрессом, автосохранением
  ответов и прямым переходом к проверке новой версии на вакансии.
- Улучшения защищены от ухудшения оценки: слабая автозамена не применяется,
  а при нехватке фактов API честно просит пользователя дополнить данные.
- `AI_PROVIDER=mock` теперь действительно работает без внешнего AI-ключа и
  даёт детерминированный эвристический результат для локальной разработки/CI.
- Добавлены `/api/health`, GitHub Actions (lint + types + build), лимит
  регистрации, безопасный auth-redirect, защитные HTTP-заголовки и удаление
  локальных файлов при удалении аккаунта.
- Проверки: ESLint, TypeScript, production build и сквозной API-smoke — зелёные.

## Сделано и проверено на живом сервере
- **Движок V3**: evidence map → LLM-скоринг (веса ТЗ §7.1) → разбор персоной →
  grounding. Прогон вживую: Вадик на «ты», по имени, score 57, цепляется за
  цитаты — качество как задумано.
- **Главная**: hero, выбор HR (фото 4:5, цитата по наведению), инлайн-загрузка.
- **Сеанс** `/session`: живой SSE-разбор + присутствие HR; режим просмотра
  готового разбора `?view=id`; рабочий шаринг → публичная карточка + ссылка.
- **Вход** `/auth`: email+пароль (next-auth), логин/регистрация, привязка
  гостевого разбора. Полный цикл register→login→кабинет проверен по куке.
- **Кабинет** `/me`: история разборов, версии до/после, вакансии, последний
  результат с фактами и выход. Рендерится с реальными данными.
- **Публичная карточка** `/toast/[slug]`: OG-картинка, вирусный CTA.
- **Цены** `/pricing`: бесплатно vs карьерный пакет (структура под биллинг).
- **HR-состав** `/hr`, **Настройки/приватность** `/settings`, удаление данных.
- Дизайн-система: графит + токсичный зелёный, Onest (локальные шрифты).

  сборку хендлеров с нативным better-sqlite3 + mammoth + pdf-parse.
  Исправлено, всё поднялось.

## Восстановлено и сохранено в recovery-ветке
- События продукта записываются в базу, а не только в консоль.
- Переход из публичной карточки связывается с загрузкой и готовым разбором.
- Закрытая воронка доступна владельцу на `/ops/funnel`.
- Старые маршруты оплаты за полный разбор удалены.
- Запрещённая продуктовая формулировка удалена из интерфейса и документации.
- «Реванш»: вопросы по конкретным слабым строкам, проверенные замены,
  связанная версия резюме и повторная оценка.
- Экспорт новой версии в настоящий DOCX и отдельная печатная страница для PDF.
- Разбор вакансии: требования, словесный шум и красные флаги.

  вступление, сопроводительное письмо и вопросы для интервью.

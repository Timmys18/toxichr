# Model receipts and lease recovery

New schema fields/tables: AnalysisLease.expiresAt, Analysis.accountingIncomplete, AiCall. Prepare target schema with the project's normal `prisma db push` procedure before running this version. No production migration was performed by this change.

`runAi` writes fsynced STARTED and COMPLETED/ERROR receipt events into `.data/ai-call-ledger.jsonl`. Analysis requests additionally write AiCall rows and immediately update known costs/tokens on Analysis. A later parser, reviewer or writer failure changes status to FAILED without deleting receipts or known spending. Repeated calls/repairs have separate IDs. A process killed during a request leaves STARTED unresolved. Missing usage and transport errors are unknown costs, never verified zero.

Receipts contain stage, model, provider, timestamps, elapsed time, token usage, application cost estimate and provider request ID when available. They contain no prompts, resume text, generated prose or keys. Cost estimates use gateway rates and are not provider billing confirmations. Unknown usage sets accountingIncomplete. Preserve the ledger on durable storage alongside the database; exporting database alone does not include standalone calls. Match the same receipt IDs between the JSONL and AiCall table; do not sum duplicates.

Export database receipts: `DATABASE_URL=file:/absolute/test-or-approved-db node scripts/export-ai-ledger.mjs /absolute/receipt-export.json`. Preserve JSONL too. Reconcile raw usage/request IDs against provider billing before filling artifacts/recovery/budget-reconciliation.json. Lost historical runs remain unresolved. Limit remains $5 including prior calls; paid acceptance gate remains blocked. The test journal is separate (`AI_CALL_JOURNAL_FILE=.data/test-ai-call-ledger.jsonl`) and contains synthetic receipts, not actual spending.

Lease policy: TTL 180s exceeds the bounded model timeout (currently <=60s), heartbeat 20s. Atomic conditional update acquires only expired leases. The previous owner cannot renew, release a successor's lease, start another accounted model call, invalidate a plan or save a completed result after ownership loss. Database writes verify ownership within their transaction. Ledger writes deliberately survive ownership loss to preserve actual spending. Cached current-version responses are checked before acquisition and while waiting. Acquiring a lease marks abandoned RUNNING analyses failed before creating a new one.

Plan policy: a semantic change or failed check removes coordinatedPlan under the lease. The current attempt stops before writer. Next attempt rebuilds all four directions from saved shared facts. Corrected or rejected old directions are never forwarded to the writer on the failed attempt. Older reports remain readable; cache requires coordinated@2 for current OpenAI results so the earlier weaker review is not silently reused.

## Streaming exclusion (2026-11-04)
Repository search of TS/JS application code found no runAiStream consumers. Its old SSE implementation was removed because it bypassed accounting and estimated price from character count. The retained exported entry explicitly throws AiConfigError before any fetch or chunk callback. It must not be re-enabled until provider usage, receipts, bounded timeouts and lease fencing are integrated and tested. This does not affect the result-page event stream, which uses the supported runAi pipeline.

# Sprint 5 — отчёт о фактически проведённой AI-калибровке

Статус: **незавершённая калибровка**. Этот отчёт не является приёмкой Sprint 5.

## Матрица и происхождение данных

В Git сохранены [18 пар резюме и вакансий](../tests/artifacts/ai/beta-calibration-cases.json) и [последний результат для каждой пары](../tests/artifacts/ai/beta-calibration-results.json). Кейсы **написаны для теста**, а не получены от реальных пользователей и затем обезличены. В матрице есть junior, senior IC, middle management, executive, технические и нетехнические, массовые и редкие роли. Исходные тексты и ожидаемые роли/уровни доступны в JSON; это не доказательство репрезентативности реальной беты.

| Сегмент | Кейсы |
| --- | --- |
| Junior | `junior-ux`, `financial-analyst` |
| Senior IC | `senior-backend`, `labor-lawyer`, `product-designer` |
| Middle management | `support-manager`, `construction-pm`, `restaurant-chef` |
| Executive | `operations-executive`, `chief-accountant` |
| Прочие middle / массовые | `sales-representative`, `warehouse-operator`, `data-scientist`, `procurement-specialist`, `clinic-nurse` |
| Сложные сценарные дополнения | `career-switch-analyst`, `regional-hr-generalist`, `field-service-engineer` |

Три новых случая моделируют соответственно переход после карьерной паузы с учебным, но не коммерческим опытом; разделённые HR-полномочия между площадкой, бухгалтерией, директором и центральной командой; командную метрику сервиса и отсутствие обязательного допуска к МРТ. Они воспроизводят **конкретные неоднозначности фактов** и уже выявили ошибку определения уровня в третьем случае, но не заменяют независимую пользовательскую выборку.

## Фактические запуски и ограничения учёта

- По журналу этой рабочей сессии: **4 вызова** live-сценария основной матрицы — ранний прерванный проход после 5 кейсов, возобновлённый проход и два повтора только неуспешных кейсов. Сохранившийся артефакт подтверждает **15 уникальных финальных результатов**, 0 ошибок и 0 записанных issues на последнем состоянии. Точное число попыток по каждому кейсу и запросов к модели **не подтверждается артефактом**: runner перезаписывал результат по ID, а `CALIBRATION_RESUME=1` пропускал уже успешные кейсы.
- По журналу сессии: **4 вызова** live-сценария rewrite — три остановки на проверках и финальный возобновлённый проход. [Артефакт rewrite](../tests/artifacts/ai/beta-rewrite-calibration-results.json) содержит **3 уникальных финальных кейса**: 2 применённых generic rewrite, 1 no-op и 3 применённых vacancy-aware adaptation. История промежуточных ответов также не сохранена.
- **Новый проверяемый проход 12.09.2026:** один полный вызов live-сценария, **18/18 уникальных кейсов, 98 зарегистрированных AI-вызовов**. [Append-only журнал](../tests/artifacts/ai/beta-calibration-run-journal.jsonl) содержит один `runId`, ID кейса, дату, версии правил, провайдера, модель и статус каждого AI-вызова, итоговый числовой score и число автоматически найденных проблем. Все 98 вызовов — `openai`, 0 `mock`, 0 ошибок вызова; у **каждого из 18** подтверждены отдельные успешные `extract`, `vacancy` и `vacancy_match`. `score` — балл анализа резюме, **не оценка качества калибровки**. Журнал не содержит резюме, вакансии, промпты, ответ модели, токены доступа или персональные данные. Старую историю он не восстанавливает.
- Финальный [GitHub Actions `suite=full`](https://github.com/Timmys18/toxichr/actions/runs/34652375721) на `cb565e7e51083dced8a993b486071b77e00646ff` выполнил 8/8 jobs, **но CI использует `AI_PROVIDER=mock`**. Он проверяет интеграцию и регрессии, не качество живых AI-ответов. Live-сценарии в обычном CI пропущены без `RUN_LIVE_AI_ACCEPTANCE=1`.

## Выявленные ошибки и точечные изменения

1. На ранних профессиях vacancy/match неоднократно отклонял strict output: ограничения `minLength` в JSON Schema не совпадали с Zod. Схемы синхронизированы в `src/lib/vacancy.ts`; правила интерпретации не менялись.
2. В нескольких match модель пересказывала `resumeQuotes`, хотя указывала существующий evidence ID. Это вызывало `непривязанная цитата`. Match Core теперь восстанавливает отображаемую цитату дословно из Professional Core по выбранному ID; неизвестные ID продолжают отклоняться. Добавлен точечный тест.
3. На senior-backend повторился отказ lexical gate по запрещённой лексике. Промпт Match Analyst уточнён нейтральными пользовательскими заменами без ослабления gate.
4. Тестовый классификатор сначала ошибочно помечал русские эквиваленты уровней, падежи профессий и `gap` с цитатой как дефекты. Его исправили; в `data-scientist` ожидаемый уровень изменён с senior на middle, потому что исходный текст не подтверждает senior. Это **изменение ожидания теста**, а не улучшение модели; считать его успешной перекалибровкой AI нельзя.
5. Rewrite runner исходно ошибочно требовал проблемную находку даже у сильного резюме. Для отдельной проверки редактора задана тестовая строка. У руководителя generic rewrite оставил текст без изменений при недостаточной полезности замены; тест теперь принимает безопасный no-op. Эти изменения касаются калибровочного сценария, не продукта.

После изменений прежний возобновлённый live-прогон дал 15/15 финальных записей без ошибок; новый независимый по времени проход дал 18/18 технически завершённых записей. Это показывает работу интеграции, **не отсутствие качественных ошибок**. Ниже — ручная проверка последнего артефакта, которая обнаружила проблемы, пропущенные автоматическим `issues: []`.

## Ручная оценка по шести критериям

Критерии: **П** — профессия и уровень Professional Core; **Г** — grounding и отсутствие выдуманных фактов; **В** — интерпретация вакансии; **М** — качество match, включая `unknown`/`gap`; **Т** — голос и мера сарказма; **Р** — редакторская пригодность rewrite/adaptation. Обозначения: `+` — приемлемо в видимом результате, `!` — дефект или сомнение, `—` — этот контур на данном кейсе не запускался. Это экспертная оценка сохранённых выводов и матрицы, а не слепая независимая разметка.

Grounding здесь означает, что видимые цитаты связаны с исходным текстом и в сохранённых выводах не найден новый конкретный факт. Это **не** подтверждение точности каждого вывода: в однострочных резюме evidence-цитата иногда равна всему резюме, что снижает проверяемость конкретного match. Два набора четырёх голосов имеют общий профессиональный абзац и только разную фиксированную концовку; формальная уникальность есть, достаточной различимости голоса нет. По rewrite старый артефакт показывает формальную привязку к подтверждённым ответам, но две замены заголовка редакторски непригодны. Новые 15 кейсов rewrite не проходили.

## Почему Sprint 5 остаётся открытым

- Нет независимой выборки реальных пользовательских резюме и вакансий; все 18 пар составлены в репозитории, хотя три новых кейса моделируют более жизненные ограничения.
- Полный per-requirement статус, объяснение и evidence ID теперь сохранены, и ручная оценка выявила повторяющиеся ошибки `unknown`/`gap`, составных требований, уровня и голоса.
- Rewrite проверен только на 3 из 18 пар, с заранее написанными подтверждающими ответами. Две замены заголовка редакторски непригодны.
- Нужно точечно исправить эти дефекты в Match Core / Professional Core / Persona Bible / rewrite validator и повторно проверить затронутые кейсы; автоматический ноль issues не является приемкой.

Следующий шаг в пределах Sprint 5: точечное исправление классификации match и редакторских замен, повторная живая проверка этих случаев, затем независимая обезличенная пользовательская выборка и повторная ручная оценка. Новый `suite=full` до завершения AI-калибровки не запускать. Журнал метаданных — предварительная точечная работа по запросу для будущего Sprint 6, не активация всего этапа.
